# Certificate Verification — DS 441 Individual Mini Project

**Student:** Trần Bảo Duy · **ID:** 28211354517 · **Course:** DS 441 A – Blockchain: Theory & Practices

Issue and verify academic certificates by a unique ID. The issuer records a certificate ID, the
recipient's address and the document hash; **duplicate IDs are rejected**; the issuer can **revoke**
a certificate and its **current validity** is shown. All rules are enforced **inside the smart
contract** (the UI only displays state), and every state change emits an event.

## Project layout

| Path | Purpose |

## Run steps

```bash
npm install            # 1. install dependencies
npm run ganache        # 2. (terminal A) start local blockchain – leave running
npm run compile        # 3. (terminal B) compile the contract
npm run deploy         # 4. deploy with account #0 (the issuer); writes web/config.json
npm test               # 5. run the automated tests (optional but recommended)
npm run serve          # 6. start the UI → open http://localhost:8080
```

In the UI choose **"Ganache accounts"** (no extension needed) or **"MetaMask wallet"** (it
adds/switches to the Ganache network; import a Ganache test private key from the Ganache output —
test accounts only). Pick an account and click **Connect**.

## How the contract enforces the rules

| Rule | Where it is enforced |
|---|---|
| Record certificate ID, recipient address, document hash | `issue(id, recipient, docHash)` |
| Duplicate IDs rejected (incl. revoked IDs) | `issue` reverts with `DuplicateId` |
| Only the issuer can issue / revoke | `onlyIssuer` modifier → `NotIssuer` |
| Revoke, no double revoke, unknown ID | `revoke` → `AlreadyRevoked` / `UnknownId` |
| Input validation | `EmptyId`, `ZeroRecipient`, `EmptyHash` |
| Current validity | `isValid(id)` = exists && !revoked |
| Hash verification | `verify(id, hash)` → `(exists, hashMatch, valid)` |
| Events for state changes | `CertificateIssued`, `CertificateRevoked`, `IssuerTransferred` |

The document hash is `keccak256` of the file bytes (or text) computed in the browser; only the
hash goes on-chain, never the document.

## Demonstration (two or more Ganache accounts)

Screenshots are in `screenshots/` (generated by driving the real UI):

1. `01-connected-issuer.png` – account #0 connected: network, account, balance, role **Issuer**, contract data
2. `02-issued.png` – **successful transaction**: certificate `DTU-2026-0001` issued to account #1 (confirmed in a block, event shown)
3. `03-verify-valid.png` – verify with the original document → **VALID**, hash **MATCHES**
4. `04-verify-tampered.png` – verify with an edited document → hash **DOES NOT MATCH**
5. `05-rejected-duplicate.png` – issuing the same ID again → **rejected** (`DuplicateId`)
6. `06-rejected-unauthorized.png` – account #2 (not the issuer) tries to revoke → **rejected** (`NotIssuer`); the contract, not the UI, blocks it
7. `07-revoked.png` – issuer revokes → confirmed, `CertificateRevoked` event
8. `08-verify-revoked.png` – verify again → **REVOKED / INVALID** (hash still matches the record, but the certificate is no longer valid)

**Explanation of the results:** the successful transactions (issue, revoke) were sent by account #0,
the issuer, so `onlyIssuer` passed and state/events changed. The rejected actions did not change
state: a duplicate ID hits the `DuplicateId` check, and account #2 hits `NotIssuer`. The UI first
simulates each call (`staticCall`) to decode the exact custom error and shows it without spending
gas; `test/test.js` also forces a real transaction from an unauthorized account and confirms it is
mined with status 0 (failed) and changes nothing.

## Test results

`npm test` → **18 passed, 0 failed** (full output in `test-results.txt`). Covered: issue + event,
stored data, verify (correct / wrong hash / unknown ID), duplicate ID, unauthorized issue (outsider
and student), unauthorized revoke, forced unauthorized transaction mined as failed, input
validation, revoke + event, validity after revoke, double revoke, re-issuing a revoked ID.

## Notes / design decisions

- `evmVersion: paris` is used when compiling for compatibility with Ganache.
- Revoked IDs stay registered, so an ID can never be reused for a different certificate.
- The UI queries the node for the latest block number directly (ethers caches it) so the displayed state is never stale.
